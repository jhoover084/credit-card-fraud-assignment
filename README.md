# Credit Card Fraud: Exploratory Data Analysis with AI

## What this notebook analyzes
`credit_card_fraud_eda.ipynb` explores a Kaggle credit card transaction dataset (999 transactions, 8 columns: distance from home, distance from last transaction, ratio to median purchase price, repeat retailer, used chip, used PIN, online order, fraud). The goal is to see which features of a transaction line up with it being fraudulent. The notebook covers loading the data, checking its structure, dropping rows with missing values (999 down to 977), single-variable plots, fraud vs. non-fraud comparisons for each yes/no variable, and two scatter plots. It stops before any machine learning.

## How I used AI
I used **Claude Sonnet 5.5** (Anthropic) through claude.ai. I wrote prompts as questions about the data (for example, "How many missing values are there per column?" and "Show me how fraud rates differ by whether a PIN was used"), and Claude generated the pandas, seaborn and matplotlib code. The key prompts are in markdown cells before each code cell, and the notebook is pre-run so all output is visible.

## Reflection

Using AI made this analysis much faster than writing every line myself. It produced working code for the loading, cleaning and plotting steps in one go, and it turned the PIN plot into a reusable function (`fraud_breakdown`) that I could apply to chip, online order and repeat retailer instead of copy-pasting four times. It also suggested useful extras I might not have thought of, like a log-scale histogram for the very skewed distance column and using medians to compare fraud and non-fraud. The danger is that someone who doesn't know data science could take all of this at face value. For example, they might see that a model or a plot looks great and not realize that only about 7.8% of transactions are fraud, so a model that always guesses "not fraud" would already be about 92% accurate. They might also not notice that the plot of distance from home looks like one giant bar because the data is so skewed, or they might drop rows with missing values without ever checking how many were removed. AI will write confident-sounding commentary whether or not it is right, so without understanding the basics, a person can't tell good analysis from bad.

I checked the AI's work instead of trusting it. After the notebook was built, I compared the numbers in the commentary against the data directly. I confirmed that 22 rows (about 2.2%) were dropped for missing values, leaving 977, which is small enough that dropping them is reasonable. I confirmed that 0 of the 117 PIN transactions were fraud and that only 2 of 319 in-person transactions were fraud, since claims like "a PIN looks protective" depend on those exact counts. I also checked the repeat retailer result, which went against what I expected (repeat retailers had a slightly higher fraud rate, about 8.1% vs. 4.9%). I knew to double-check it because it didn't match common sense, and when I looked at the counts, only 103 transactions were at non-repeat retailers, so the difference is based on a small group and shouldn't be over-interpreted. In general I knew to verify things when a claim depended on a specific number, when a result seemed surprising, or when the sample behind a conclusion was small.
